# v2-civ 全国版规划方案

> 状态：方案已确认（采用推荐项，见第 9 节）。P0 + P1 已在 `national` 分支实现（2026-11-09），见下方「实现进度」。依赖 `docs/城市规模与据点方案.md`（城市分档、落位、聚落格），本方案在它之上把地图从长三角扩到全国。

## 实现进度（2026-11-09）

**已完成（P0 + P1，外加 P2 的地形部分）**
- **全国古舆图**（`v2-civ/src/china.js`）：默认首页。地貌晕渲 + 国界 + 省界 + 江河湖泊 + 省名 + 南海诸岛插图 + 罗盘；12 座有社群的城市挂旗标，离得近的自动合并成片区旗（如"长三角 · 7"）。拖拽、滚轮、双指缩放；点旗标放大淡出后进入对应 3D 区域；3D 里点"全国地图"或一直往外滚就回到全国。
- **城市表**（`src/data/china-cities.json`）：全部地级行政区、直辖市、特别行政区和省直辖县（369 个），按行政区划代码，坐标取驻地。县级市目前只收有社群的（常熟）。"福建"这类写省名的记录，自动落到 otherCities 的第一个城市（爱拼游戏社 → 厦门，福州作为分会城市）。
- **3D 区域**：没有做"全国一张网格 + 地形分块流式加载"，而是**按片区分成独立 3D 场景**，每个 600 × 540 公里、一次只加载一个（约 0.3–0.5 MB）。现有 7 个区域：长三角、京津、成渝、珠三角、关中、辽沈、闽南闽东，地形都已烘好（相当于提前做了 P2 的地形部分）。效果和方案一致：远看古舆图、近看 3D、只加载附近；实现更简单，也不用改长三角已有的坐标和落位。
- **区域通用化**：高程上限按区域自动定（成渝 5100 米、关中 3200 米……），地貌和山形按"高出本区域低地多少"判断；迷雾开拓范围、道路、古舆图上的城市名、开场巡游，在长三角以外都按城市自动生成。长三角保留手做内容（黄山、西湖、运河、Ludere 商路、地名）。

**和方案的差异**
- 投影：全国古舆图用阿尔伯斯投影；3D 区域仍用各自中心的局部平面坐标（600 公里内变形可以忽略）。
- 新城市还没有地标和地域风格城池（P3），统一用现代 CBD。
- 新区域的地表仍是长三角那套配色（水田、林地），沙漠、黄土、雪山等地表类型（3.4 节）还没做。

**还没做**
- P3：6 种地域风格城池、一级地标（先做现有 12 城）。
- P4：多城社群的分会旗和商路、自然奇观。
- 新地表类型、更多县级市、港澳台社群收录（待运营决定）。
- **地图合规（3.2 节）仍待定**：现在的边界来自 DataV.GeoAtlas（高德），只用于开发，正式公开前要换成标准地图服务数据并确认审图流程。

## 1. 起点：现在有什么、差多少

**现有数据**：19 个社群，分布在 12 个城市（杭州 3；北京、西安、成都、深圳、南京各 2；天津、上海、常州、重庆、沈阳各 1；另有 1 条记录写的是省名"福建"，实际在厦门、福州）。最北沈阳（北纬 41.8°），最南深圳（22.5°），最西成都（东经 104°），最东上海（121.5°）。

**现有地图**：只覆盖长三角，600 × 540 公里，一格六边形宽约 11 公里（外接圆半径 6.5 公里）。很多东西是按这块小区域写死的：

| 写死的地方 | 文件 | 全国版的问题 |
|---|---|---|
| 投影是以北纬 31.1° 为基准的简单平面换算 | `config.js` `toWorld` | 小区域没问题，铺到全国后东北、海南的形状和距离会明显变形 |
| 地图边界 `XMIN…ZMAX`、高程图 800×720、水域图 1200×1080 都是一整张 | `config.js`、`terrain.js` | 全国按同样精度约 6900×5500 像素，手机显卡放不下一张这么大的贴图 |
| 高程上限 1900 米，8 位灰度 | `config.js` `HMAX` | 青藏高原、珠峰会被截断 |
| 地表配色只有长三角的水田、丘陵、湖 | `terrain.js` `biomeCol` | 没有沙漠、戈壁、高原、雪山、草原、黄土、喀斯特 |
| 六边形数据贴图 64×64，领土颜色最多 32 种 | `config.js` `HEX_N`、`terrain.js` `MAX_OWNERS` | 全国约 460×420 格；有社群的城市以后会超过 32 个 |
| 羊皮纸迷雾、运河、黄浦江、商路、黄山、雷峰塔都是手画坐标 | `parchment.js`、`routes.js`、`wonder.js` | 需要换成数据驱动，手工内容只留给重点城市 |
| 城市列表、地标、颜色手写在 `CITIES` | `data.js` | 全国 300 个地级市不可能手写 |
| 镜头距离 30–470 公里 | `camera.js` | 全国视野需要 4000 公里以上 |

## 2. 核心思路

### 2.1 远看是古舆图，近看是 3D（推荐）

全国尺度下，一格 11 公里的 3D 地形在屏幕上只有几个像素，社群根本看不见，而且同时渲染全国 3D 地形会让手机卡死。所以分成两层：

- **远景：全国古舆图（2D）。** 沿用现在羊皮纸迷雾的画风，画出全国海岸线、主要江河、山脉墨线、省名。城市显示成旗标，标出社群数和档位。这一层就是一张（或几张分级的）贴图加一层 HTML 标记，手机也很轻。类似《文明6》的"战略视图"。
- **近景：现在这套 3D 地形。** 镜头拉近到某个城市一带时，从古舆图淡入 3D，只加载镜头附近的地形块。
- **切换：** 按镜头高度交叉淡入。点城市时，镜头先拉远、平移、再推近（像 Google 地球那样），不是硬切。

另一种做法是全程 3D、远处降精度。效果更连贯，但工作量和手机性能风险都大得多。我不推荐首版这样做。

### 2.2 没有社群的地方保持"未探索"（推荐）

全国只有有社群的城市周围才渲染 3D 地形，其他地方一直是古舆图迷雾。这样做有三个好处：

1. **性能**：全国虽大，真正要画的只是十几块城市区域。
2. **叙事**：每新增一个社群，地图上就"开拓"出一片新疆域，正好呼应《文明6》的开图，也鼓励用户上传。
3. **工作量**：地形、地表、地标只需要先在有社群的区域做好。

开拓范围 = 城市领土外再加一圈缓冲（约 3 格，30 公里左右）。相邻城市的开拓区连在一起时，就合并成一整片，比如长三角、珠三角、京津。

### 2.3 六边形和城市规则不变

格子大小保持外接圆半径 6.5 公里，`城市规模与据点方案` 里的分档、落位、聚落格、领土争夺规则原样沿用，只是从"一块地图"变成"全国一张统一网格"。全国约 460×420 ≈ 19 万格（含海），其中陆地约 8.7 万格。用一张 512×512 的数据贴图就能装下整张全国网格，这在手机上也不是负担。

## 3. 地理底座

### 3.1 投影

改用中国地图常用的**阿尔伯斯等积圆锥投影**：中央经线东经 105°，标准纬线北纬 25° 和 47°。全国面积和形状都基本准确。`toWorld` 只改这一个函数，其他代码继续用"1 单位 = 1 公里"的世界坐标。

南海诸岛按标准地图惯例，在古舆图上放一个**右下角插图**，不进 3D 世界。

### 3.2 地图合规（上线前必须处理）

在国内公开发布中国地图，国界线、台湾、南海诸岛、藏南、阿克赛钦等的画法都有要求。现在用的 Natural Earth 边界**不符合**这些要求。长三角样片不涉及国界，全国版就绕不开了。建议：

- 国界、省界、海岸线用自然资源部"标准地图服务"或带审图号的数据源，不用 Natural Earth 的边界。
- 古舆图上的国界和南海插图严格照标准地图画，不做艺术变形。
- 正式上线前，确认是否需要申请审图号，或者咨询相关的专业人士。

这一条会影响上线时间。建议和开发并行推进，不要放到最后。

### 3.3 地形分块与烘焙

| 数据 | 精度 | 全国规模 | 处理方式 |
|---|---|---|---|
| 高程 | 0.75 公里/像素，16 位 | 约 6900×5500 | 切成 256 公里见方的块，约 360 块，其中含陆地的约 210 块 |
| 水域距离场 | 0.5 公里/像素 | 约 10400×8200 | 同样分块 |
| 地表类型（新） | 1 公里/像素 | 约 5200×4100 | 来源：ESA WorldCover 或 MODIS 土地覆盖，归并成十几类 |
| 全国概览高程 | 4 公里/像素 | 约 1300×1000 | 一整张，给远景和过渡用 |
| 古舆图底图 | 分 2–3 级 | 最大约 4096 宽 | 烘焙成 webp |

- **每块约 300 KB**，全部烘焙下来约 60 MB。首屏只加载古舆图和城市索引，大约 1 MB。
- 烘焙脚本在现有 `scripts/fetch_dem.py`、`bake.py` 基础上改成"按块"运行。产物不放进 `main` 分支（避免仓库变大），而是由 GitHub Actions 烘焙后放进 Pages，或者放进单独的数据分支。
- **高程**改成 16 位（两个通道），上限 9000 米。高度夸张曲线 `EXAG/EXP` 要重新调，保证青藏高原不会变成一堵墙，长三角的丘陵也不会被压平。
- **江河湖**：Natural Earth 10m 的全国江河（长江、黄河、珠江、松花江…）和湖泊（青海湖、鄱阳湖、洞庭湖…）直接可用。运河、城市内河这类细节只给重点城市手画。

### 3.4 地表类型扩充

在现有配色基础上，加这些地表，并按地表类型分配植被和小物件（`props.js`）：

| 新地表 | 代表地区 | 画面要点 |
|---|---|---|
| 沙漠 | 塔克拉玛干、腾格里 | 沙丘纹理 |
| 戈壁 | 河西走廊、内蒙古西部 | 碎石、红褐色 |
| 高原草甸 | 青藏高原 | 低矮、黄绿 |
| 雪山冰川 | 喜马拉雅、天山 | 山顶积雪随海拔出现 |
| 温带草原 | 内蒙古、呼伦贝尔 | 大片草色，少树 |
| 黄土高原 | 陕北、甘肃东部 | 梯田、沟壑 |
| 喀斯特 | 桂林、贵州 | 尖峰林立，用小物件做 |
| 针叶林 | 东北、云杉林 | 深绿尖顶树 |
| 热带 | 海南、西双版纳 | 椰树、阔叶 |

PR #3 的"手绘地表贴图"如果合并进来，新地表也按同一套贴图方式做，画风才统一。

## 4. 城市与地标

### 4.1 全国城市表

- 收录全部地级行政区和直辖市（约 330 个），再加县级市（约 390 个）。用**行政区划代码**作主键，坐标取政府驻地。
- 这张表在构建时生成。城市颜色按代码自动配色，同省的城市用相近色系，相邻城市保证不撞色。
- 只有"出现过社群"的城市才在地图上渲染城池。其他城市在古舆图上只显示一个小地名，或者干脆不显示。

### 4.2 城池按地域分风格

300 个城市不可能每个都手做。城池（城市中心那一格）按省份分成 6 种地域风格：

| 风格 | 省份 | 特征 |
|---|---|---|
| 北方方城 | 京津冀、山东、河南、山西 | 方正城墙、灰瓦、城楼 |
| 江南水城 | 江浙沪、皖南 | 白墙黛瓦、水门（就是现在这套） |
| 岭南 | 广东、广西、海南、福建 | 骑楼、镬耳墙 |
| 西南山城 | 川渝、贵州、云南 | 依山叠落、吊脚楼 |
| 西北 | 陕甘宁、新疆 | 夯土城、角楼 |
| 东北 | 黑吉辽 | 厚墙、大屋顶、雪 |

### 4.3 地标分三级

- **一级（手做专属地标）**：社群最多、最常被访问的约 20 个城市。北京天坛、西安大雁塔、成都、重庆洪崖洞、深圳、广州塔等。现在的东方明珠、天宁塔、方塔、雷峰塔、中华门都保留。
- **二级（模板地标）**：塔、楼阁、桥、牌坊这类，按城市挑一种组合，配上城市名。
- **三级**：没有地标，只靠地域风格的城池。

自然奇观（现在只有黄山）按同样的思路逐步加：泰山、桂林山水、张家界、长白山天池、珠峰等。

### 4.4 省级、多城记录

现在的"福建"那条记录（爱拼游戏社，覆盖厦门、福州），以及以后类似"某省高校联盟"的社群：

- **主城**落在一个具体城市（让用户选，默认是第一个城市）。
- `otherCities` 里的城市各放一面"分会旗"，不占格子，点开指向主城的社群。
- 主城和分会之间画一条**商路**（就是现在 Ludere 上海—常熟那条的通用版）。全国视图里显示成虚线，拉近后在 3D 里显示商队。

## 5. 界面与交互

- **全国视图**：城市旗标按档位决定大小。镜头远时，相邻城市自动合并成一个区域标记（例如"长三角 · 9 个社群"），拉近后再展开。
- **导航**：城市列表按省份分组，可搜索、可按社群数排序；点城市自动飞过去。地址栏 `?view=chengdu` 这类参数继续可用，方便分享。
- **开场动画**：先在古舆图上依次点亮有社群的城市，再推近到"离用户最近"或"社群最多"的城市。精确到用户所在城市需要定位权限，首版不做，最多按时区和语言简单猜。
- **手机**：远景始终只是 2D，近景沿用现在的降画质规则，同时最多只加载 4 块地形。

## 6. 性能预算

| 项目 | 目标 |
|---|---|
| 首屏下载 | ≤ 2 MB（代码 + 古舆图 + 城市索引） |
| 每次飞入一座城 | 额外 ≤ 1.5 MB（4–6 块地形） |
| 同时驻留的地形块 | 桌面 ≤ 16 块，手机 ≤ 6 块，离开后释放 |
| 帧率 | 桌面 60，中端手机 30 以上 |

## 7. 分阶段实施

| 阶段 | 内容 | 完成后看到什么 |
|---|---|---|
| **P0 底座** | 全国城市表（行政区划代码）、数据清洗（"福建"这类记录）、换阿尔伯斯投影、全国统一六边形网格、数据贴图和领土颜色改成可扩展 | 长三角画面不变，但坐标体系已经是全国的；落位结果重新钉住并核对 |
| **P1 全国古舆图** | 全国古舆图底图、南海插图、城市旗标、远近切换和飞行镜头；其他城市先显示城池和社群，地形用概览高程顶替 | 能看到全国 12 个城市并飞过去；长三角保持现在的完整画质 |
| **P2 地形分块** | 分块烘焙流水线、按需加载、16 位高程、地表类型扩充、全国江河湖 | 每个有社群的城市都有正式 3D 地形，西安的黄土、成都的盆地、沈阳的平原各不相同 |
| **P3 城市风格** | 6 种地域城池、一级地标（先做现有 12 城）、二级模板地标 | 各城一眼能认出来 |
| **P4 连接与内容** | 多城社群的分会旗和商路、区域合并标记、自然奇观 | 社群之间的联系在地图上可见 |
| **并行** | 地图合规（标准地图数据、审图号） | 能正式公开全国版 |

P1 结束就可以先上线一个"全国可浏览"的版本，P2、P3 逐个城市补齐画面。

## 8. 和现有工作的先后关系

全国版会大改 `config.js`、`terrain.js`、`main.js`、`world.js`、`camera.js`、`parchment.js`。PR #3（画面升级）和本地的城市分档改动也在改其中好几个文件。**建议先把这两项定下来并合并进 `main`，再开始 P0**，否则三边会互相冲突，合并很痛苦。

## 9. 决定

| # | 问题 | 结论 |
|---|---|---|
| 1 | 远近两层，还是全程 3D | **两层**：远景 2D 古舆图，近景 3D |
| 2 | 没有社群的地方是否保持迷雾 | **保持**，只开拓有社群的区域 |
| 3 | 地图合规谁来跟进、用哪个底图数据源、要不要申请审图号 | **待定**，需指定负责人；P1 公开上线前必须定 |
| 4 | 县级市单独成城还是并入地级市 | **有社群就单独成城**，规则同常熟 |
| 5 | 港澳台 | 底图必须完整（合规要求）；当地社群是否收录、如何标注，**待运营决定** |
| 6 | 一级地标先做哪些城市 | **现有社群所在的 12 个城市** |
